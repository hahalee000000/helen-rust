# /goal 命令快速开始

## 什么是 /goal 命令？

`/goal` 是 Helen WebUI 的新功能，让 agent 能够自主完成复杂的多步骤任务。它会：
1. 接收你的目标描述
2. 自动规划并执行任务
3. 在每轮迭代后评估进度
4. 如果目标未完成，自动继续下一轮
5. 直到目标完成或达到最大迭代次数（10 轮）

## 使用方法

### 基本语法
```
/goal <目标描述>
```

### 示例

#### 简单任务
```
/goal 写一个 Python 计算器
```

#### 复杂任务
```
/goal 实现一个完整的 HTTP 服务器，包含：
- 路由系统（GET/POST）
- 中间件支持
- 错误处理
- 单元测试
- README 文档
```

#### 代码重构
```
/goal 重构 user 模块：
1. 提取公共函数到 utils
2. 添加类型注解
3. 编写单元测试
4. 更新文档
```

## 完成标记

Agent 会在每次回复末尾标注状态：

### [GOAL_COMPLETE]
表示目标已完成，后跟总结。
```
[GOAL_COMPLETE] 最终总结：所有功能已实现并通过测试。
```

### [GOAL_IN_PROGRESS]
表示目标未完成，后跟剩余工作。
```
[GOAL_IN_PROGRESS] 还需要做什么：实现错误处理和编写文档。
```

## 前端显示

### 进度提示
每轮迭代开始时，前端显示：
```
🎯 目标 Pursue 中... 第 N/10 轮
```

### 完成消息
目标完成时，显示：
```
✅ 目标完成
<总结内容>
共 N 轮迭代
```

### 达到最大迭代
如果 10 轮后仍未完成：
```
⚠️ 达到最大迭代次数 (10)
<当前进度总结>
共 10 轮迭代
```

## 中断任务

在 goal 循环进行中，你可以：
1. 点击前端的"停止"按钮
2. 或发送新消息（会自动中断当前任务）

## 最佳实践

### ✅ 推荐
- **明确目标**: "实现 HTTP 服务器" 比 "做点什么" 更好
- **分解复杂任务**: 如果任务很复杂，考虑分成多个 /goal
- **监控进度**: 查看每轮的进度提示，了解 agent 的工作状态
- **适时中断**: 如果方向错误，及时中断并重新描述目标

### ❌ 避免
- **模糊目标**: "改进代码" 太模糊，应该具体说明改进什么
- **过大范围**: 一次实现整个应用可能超出 10 轮限制
- **忽视成本**: 多轮迭代会消耗大量 token，注意成本控制

## 技术细节

### 迭代上限
- 默认最多 10 轮迭代
- 每轮使用 actor 的 max_turns=100
- 总工具调用上限：1000 轮

### 完成检测
- **主要**: LLM 自报告（[GOAL_COMPLETE] / [GOAL_IN_PROGRESS]）
- **回退**: 简单启发式（检测"完成"、"done"等关键词）

### 上下文管理
- 依赖 actor 的 graduated compression 自动压缩
- goal 文本在每次续传 prompt 中重复，确保不会丢失

## 常见问题

### Q: 如果 10 轮后目标还没完成怎么办？
A: 你可以：
1. 发送新的 /goal 继续未完成的工作
2. 或者调整目标，使其更小更具体

### Q: 如何知道当前在第几轮？
A: 前端会显示 "🎯 目标 Pursue 中... 第 N/10 轮"

### Q: 可以修改最大迭代次数吗？
A: 目前固定为 10 轮。未来版本可能支持配置。

### Q: 中断后可以恢复吗？
A: 目前不支持断点恢复。中断后需要重新开始。

### Q: 会消耗很多 token 吗？
A: 是的，多轮迭代会消耗大量 token。建议：
- 使用明确的目标准备
- 监控轮次进度
- 必要时及时中断
